# Lint 菜单 —— `Tools › PromptUGUI › Lint All UI XML`（分支 `feat/lint-menu`）

> 状态：**已实施**。设计不单独出 spec：菜单本身是 UIXmlLint CLI 的第二个前端，规则、两遍走法、finding 的拼写
> 全部沿用 `2026-08-26-theme-driven-style-design.md` §9；commons 的合并语义与本分支的 L1–L3 规格在
> `2026-09-18-commons-settings-design.md` §4.7–§4.9、§13（"feat/lint-menu 接手"）。

## 1. 目标

在宿主 Unity 里一键 lint 用户工程的全部 `.ui.xml`，结果进 Console、每条可点 ping 到资产。与 CLI **同一份实现**：
前端只决定「文件从哪来、`src` 怎么变成文件、行往哪打」。

## 2. 落地（按提交）

### L0 `8cdff18` —— 菜单 + 共享实现抽出

- `Runtime/Core/Lint/ImportClosure.cs`（纯 C#）：`ResolveInResources`（CLI 原来的 Resources 上溯猜测）+ `TryLoad`
  （all-or-nothing 的 Import 闭包预取），`exists` / `read` 走委托，Core 不碰文件系统。
- `Runtime/Core/Lint/LintRun.cs`（纯 C#）：读 → 解析 → 闭包 → `DocumentLinter.Walk` → `file:line: [CODE] msg (via …)`
  拼写 → 跨入口去重；finding 带 `Kind`（Error / Issue / Note）与要打开的文件；`Files` / `Issues` 计数。
- `.lint/UIXmlLint/Program.cs` 收窄到参数展开 + 打印。重构前后在 `Runtime/Resources/`、`Samples~/`、ssw `Assets/` 上
  输出逐字节相同。
- `Editor/UIXmlLintMenu.cs`：
  - 扫 `AssetDatabase` 里 `Assets/` + **embedded** 包的 `.ui.xml`（Local / registry / git 包是别人的，不扫）。
  - `<Import src>` 先查 **Addressables** 的地址 / GUID → asset path（`AddressableAssetSettings.GetAllAssets`，
    `PROMPTUGUI_HAS_ADDRESSABLES` 门），再退回 `ResolveInResources`；CLI 只有后者。
  - `Packages/<name>/…` 是虚路径，`FileUtil.GetPhysicalPath` 映射到真文件；反向 `ToAssetPath` 把任意注册包内的
    文件映回 `Packages/<name>/…`，Console 才能 ping。
  - Error → `LogError`（不可读 / 解析失败 / `PUI-EXPAND`，即 `UI.Open` 会抛的）；Issue → `LogWarning`；Note → `Log`。
- 测试：`ImportClosureTests` / `LintRunTests`（EditMode，委托伪文件系统）、`UIXmlLintMenuTests`（EditorOnly：
  磁盘 Import 解析、Local 包路径读取、asset ↔ physical 映射、归属过滤）。

### L1 —— commons 进闭包（spec §4.7、§7-21、§7-22）

- `ImportClosure.TryLoad(entryPath, entry, resolve, read, commons, cache, out applied, out unresolved)`：
  入口自己的 Import 先走；每条 commons 行按 **入口文件** 解析（短 key 从入口目录上溯，与写在入口里的 `<Import>` 同规则）、
  递归它自己的 Import；任一行解析不到 → 整个闭包 null（半个 commons 会报幻影 unknown）。
  - `ImportClosure.Cache`：一次 run 内 src → (file, doc) 共享，commons 闭包只解析一次（§7-22 读计数）。
  - **入口本身就是某条 commons 时把那行剔除**（`applied`）：目录递归会把 DefaultTheme 当入口扫到，合并到自己身上
    每个样式都会 `conflicts with commons pool`——ssw 上真撞到了。
- `LintRun.Lint(path, read, resolve, commons)`：
  - Note 文案区分 `common library src="…"` 与 `<Import src="…">`；commons 解析不到的 Note **一次 run 只出一次**，
    新增 `Skipped` 计数让汇总说清「N of M 文件只跑了 raw 遍」——否则一条 Note 会掩盖整个目录都没展开。
  - 闭包为 null 时仍把 `commons` 传给 `Walk`：没有任何 `<Import>` 的入口否则会被单独展开、把每个 commons 名字报成 unknown。
  - 行的 `as` 含 `.` → 一次 run 一条 Error（settings `OnValidate` 的 CLI 侧镜像；`File` 为 null）。
  - `SawUnknownName`：本次 run 出现过 unknown style / template 的 `PUI-EXPAND`，给 §4.8 的末尾提示用。

### L2 —— 菜单读 settings（spec §4.8、§7-25）

- `UIXmlLintMenu.ConfiguredCommonLibraries()`：`PromptUGUISettings.Instance?.commonLibraries` → `ImportRef`（空行剔除、
  空 `as` 即无命名空间），`Lint(paths, report, commons)`。
- 末尾提示：`SawUnknownName && commons.Count == 0` → 一条 Info 指向 settings 的 Common Libraries。
- `Report`：`File == null` 的配置类 finding 不带 context。

### L3 —— CLI（spec §4.9、§7-32）

- `--settings <file.asset>` / `--commons <src>[@<as>]`（可重复，不读资产）/ 都不给 → **自动发现**：每个入口向上最近的
  `Assets/`，先找 `PromptUGUI_Settings.asset`，没有再扫 `**/*.asset` 头 4 KB 的 `m_Script` guid；多个取排序后第一个并 stderr 提示。
  用了哪个资产、声明了哪些行打到 stdout。显式 `--settings` 读不到或不是 settings → exit 2。
- `--src-root <dir>`（可重复）：Resources 上溯失败后再试 `dir/src.xml`、`dir/src`。
- `Skipped > 0` 时 stdout 一行「N of M 文件跳过展开遍」+ `--src-root` 提示；`SawUnknownName && 无 commons` 时同 §4.8 提示。
- README：新增「Common libraries」节、`--src-root` 说明、用法示例、exit 2 语义；删掉过时的「No cross-file resolution /
  No Template expansion」两条。

## 3. 与 spec 的出入

- §4.7 写 `TryLoad(..., commons, out unresolved)`；实际多一个 `out applied`（剔除入口自身那行后的列表），因为 `Walk`
  拿的列表必须与闭包一致，否则 `lookup(自身 src)` 为 null 直接 `PUI-EXPAND`。
- §4.7 没写的：`LintRun.Skipped` 计数与两端汇总（理由见 L1）。
- §4.9 的 `--src-root` 允许重复给（多个根无害）。
