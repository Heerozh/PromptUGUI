# 公开浮层 `<Popover>` Implementation Plan

> **For agentic workers:** 按 Task 顺序执行，步骤用 checkbox（`- [x]`）跟踪。每个 Task Red 先行。
> 设计依据：`docs~/superpowers/specs/2026-10-19-popover-design.md`（下称 spec，§ 号都指它）。
> 2026-10-19 与作者对齐（spec §13 的 PO-D1…D15 按推荐）；计划期修正与审阅结论（P1–P26）在 Task 0 写回 spec。

## Context

浮在页面之上、贴着某个元素的面板，今天只能手写：一块普通面板，C# 切 `Hidden`。典型用法有聊天表情选择、列表行「…」菜单、右键菜单、点数值看构成。手写的面板有这些问题：
- 点外面、按 Esc 或 B 都不会关，被模态盖住也不收；
- 出不了所在容器的 mask；
- 不会翻面、不会夹边；
- 手柄焦点进不去。

阶段 0 抽出的浮层内核，只服务「面板挂在宿主之下」的 `<TabMenu>` 与 `<Suggestions>`。

spec 已定的方向：
- 公开一个独立的 `<Popover>`，用 `on="click@id"` 或 C# 指向锚点；
- 外部按下默认穿透（`dismiss="pass"`）；
- 输入框不对抗失焦，另加 `InputField.Insert`；
- `<Show>` 认 `expand` / `collapse`。

**Goal：**
- `<Popover>` 控件本身；
- 内核扩展：自由框定位（锚点不是面板的父物体）、四向侧放与对齐、外部按下的穿透探测、按锚点认祖先、宿主被停用即收、深度告警；
- `<ScrollList>` 的行换项时通知浮层；
- `<Show>` 认 `expand` / `collapse`；
- `InputField.Insert`；
- lint、XSD、样例、文档。

**Architecture：**
- **内核**（`Controls/Internal`）：
  - `PopupPlacer.SolveSide` 是纯函数：四侧 × 三对齐，两侧都放不下时沿主轴推回边界内。
  - `PopupLayout` 可以带「画布空间目标矩形 + 侧 + 对齐」。带了，`PopupCore` 就走自由框：只换算坐标、按侧设 pivot、不写 sizeDelta。没带，就是今天的「宿主子物体」路径，TabMenu / Suggestions 不动。
  - 过渡改为补间一个位移分量（P17），关闭淡出期间不再挡指针（P18）。
  - 新增 `PopupDismiss.PassThrough`；`IPopupEntry` 加 `Anchor` / `Blocker` / `Dismiss` / `OpenFrame`。
  - `PopupChain` 的扩展：
    - 按「宿主或锚点」认祖先；
    - `DismissUnder(root, reason)` 也认锚点；
    - 新增 `Prune()`，在每个查询点先清掉失活的项；
    - 新增纯函数 `OutsideCloseFrom(hit, pressFrame)`。
  - 面板守卫 `PopupPanelGuard`（`[DefaultExecutionOrder(-1000)]`），在 Play 模式下：
    - `Update` 驱动探测；
    - `LateUpdate` 回调宿主；
    - `OnDisable` 排一次下一帧的清理。
  - `OutsidePressProbe`：在 `InputSystem.onAfterUpdate` 里锁存按下，再 `RaycastAll`；测试可以注入。
- **控件**：`Popover : ProceduralControl, IExpandable`。
  - 面板就是它自己的 GameObject，上面挂：Image 表面、`VerticalLayoutGroup`、`PopoverFitter`（`ILayoutSelfController`）、`PanelSink`、`ExpandableMarker`。
  - `Control.OwnsGeometry` 让 `ApplyCommon` 只解析尺寸、写 `interactable`，其余几何一概不写。
  - `on=` 的源解析统一走实例化收尾：Screen 打开时用 `Screen.DeferDuringOpen`；动态子树用 `ScreenInstantiator.DeferAfterBuild`。
- **周边**：
  - `ScrollList` 在 `Retire` / `Park` / `TakeRow`（`_leaving` 分支）调 `PopupChain.DismissUnder(row, AnchorLost)`；`PermuteSlots` 同步移动绑定快照。
  - `<Show>` 的 `expand` / `collapse` 走源头登记（`IExpandable.RegisterExpandShow`，同 `checked`）。
  - `PuiInputField` 记下光标；`InputField.Insert` 走程序写入路径。

**Tech Stack：**
- Unity 6 / C# 9
- uGUI：Canvas overrideSorting、GraphicRaycaster、VerticalLayoutGroup、`ILayoutSelfController`
- TMP（ugui 2.x）
- Input System：`onAfterUpdate` 锁存，`#if ENABLE_INPUT_SYSTEM … #elif ENABLE_LEGACY_INPUT_MANAGER`
- R3、LitMotion
- 不引入新包

## 已对齐的决策

spec §13 的 PO-D1…D15 按推荐执行。下表是计划期补充：读码、三路调研、一轮设计审阅得出的结论，Task 0 写回 spec。

| # | 决策 | 为什么 |
|---|---|---|
| P1 | `VerticalLayoutGroup` 与 `PopoverFitter` 都挂在面板自己身上，`ChildHostTransform` 就是它自己 | 程序化表面节点自带 `LayoutElement.ignoreLayout`（`ProceduralSurface.cs:233`），`<Decor>` 不参与布局。面板是布局根，内容一变，fitter 就在同一次重排里跟着跑；如果 VLG 挂在子节点上，`MarkLayoutForRebuild` 停在子节点，父节点上的 fitter 永远轮不到。`<Add into="#pop">` 也正好落进面板 |
| P2 | `PopupLayout` 加可选的「画布矩形 + 侧 + 对齐」；有它就走自由框，不新增构造参数 | TabMenu / Suggestions 的调用与 `PopupCoreTests` 原样不动 |
| P3 | 外部按下的判定做成 `PopupChain.OutsideCloseFrom(Transform hit, int pressFrame)`，纯函数，可以用假条目单测。设备与射线放在 `OutsidePressProbe`，测试注入两样：`PressesForTests`（位置 + 帧号 + 批次号）、`HitForTests`（绕过射线）。真射线只在 PlayMode 测 | EditMode 给不了 Overlay Canvas 确定的尺寸；EditMode 测试程序集也不引用 Input System |
| P4 | 「打开那一帧的按下不算」按帧号比较：条目记 `OpenFrame`，按下带自己的帧号。探测按批次号去重，不按 `frameCount` | `Time.frameCount` 在 `[Test]` 内不前进 |
| P5 | **不在 `OnDisable` 里关浮层。** `PopupChain.Prune()` 把面板为 null 或 `!activeInHierarchy` 的项按 `HostGone` 关掉。它在每个查询点之前先跑一遍：`Push`、`Top`、`EscapeChain.Decide`、`DismissBelow` / `DismissUnder`、探测。守卫的 `OnDisable` 只在 Play 模式下用 `Awaitable.NextFrameAsync()` 排一次下一帧的清理。守卫不需要 `[ExecuteAlways]` | `OnDisable` 正在停用层级时，关闭路径会 `SetActive(false)`，Unity 拒绝（「already being activated or deactivated」）；`Closed` 的订阅者也会在这棵正在停用的层级里 `SetActive`。§1.2-5 的 Red 测试在 EditMode 走「Esc → 清理 → 模态」 |
| P6 | 跟随写成 `Popover.Follow()`：守卫的 `LateUpdate` 调它，测试调 `TickForTests()`。可交互判断：有 Selectable 用 `Selectable.IsInteractable()`，否则用 `PeekInteractable`。裁切检查求所有 `RectMask2D` 祖先的 `canvasRect` 交集，遇到 overrideSorting 的 Canvas 就停（同 `MaskUtilities`）。锚点可能在两次 `LateUpdate` 之间被销毁，`Measure` 要接住。角点数组复用同一个缓冲 | 不能用 `IControl.Interactable` 的 getter：它会懒建 CanvasGroup（`Control.cs:79-88`）。不在 overrideSorting 处停的话，锚在另一个浮层里的锚点会被背后的列表误判为「被裁掉」 |
| P7 | `Control.Hidden` 改为 `virtual`。Popover 覆写：读到的是 `!IsOpen`；写 `true` = `Close()`；写 `false` 什么都不做 | 基类的 `Hidden = false` 等于 `SetActive(true)`，会把关着的面板直接亮出来——没进链、没定位 |
| P8 | `OwnsGeometry` 分支：解析 `SizeSpec`，交给 `internal virtual void ApplyOwnSize(SizeSpec)`，再照常写 `interactable` 后返回。具体约束：<br>• 不解析 `anchor` / `pivot` / `margin`，免得被忽略的属性在解析时抛错；<br>• 不应用 `hidden`；<br>• 父节点是布局组时，只挂 `ignoreLayout`；<br>• `Screen.ApplyScaleToNodeCore` 跳过这类控件；<br>• lint 的 `CheckHugScale` / `CheckClampScale` 豁免 `<Popover>`（`scale` 本来就被忽略，只给警告） | 如果走 `hidden`：`hidden.portrait` 没有基值时，转个屏浮层就会被关掉。如果写 scale：盒子补偿会写到面板上 |
| P9 | `gap` 做成 string setter | `float` 型属性写成非数时，`ControlMeta.cs:87-90` 的 `float.Parse` 直接抛错，到不了 setter |
| P10 | `TriggerSourceResolver.ResolveId` 的参数从 `Trigger` 放宽为 `Control`，再加一个可选的 `label`，`<Trigger>` 既有的报错消息不变。新增 `FindTriggerBtn(Control from, string id, string label)`：跳过自己的子树，并要求找到的是 `<Btn>` | 浮层自己子树里的同名 `<Btn>` 是错误，不是触发钮 |
| P11 | ScrollList 的钩子只挂三处，都按调研定点：<br>• `Retire`：挪进池子与 `Dispose` 之前；<br>• `Park`：`ReleaseSubscriptions` 之前；<br>• `TakeRow` 的 `_leaving` 分支。<br>三处都包进 `LoseAnchors(host)`：链为空就直接返回，否则在内部保存并设置 `_inSync = true`，调完再恢复。同一项的重绑路径一概不挂 | 推送会重绑每一行。`VirtualPush` 的 `ClearSlots` 与 `RemapRealized → Park` 本来就在 `_inSync` 之外执行；浮层的关闭回调里再推送同一个列表时，不设这个标志就会在迭代过程中重入 |
| P12 | `PermuteSlots`（`ScrollList.cs:443-448`）同步移动绑定快照：新增 `IItemBinding.Move(from, to)`。单独一个提交，Red 先行 | 今天带 key 的列表拖动排序之后再推送，被拖的行会和邻行互换内容：标签看着对，行身份错了。修掉之后，复用的行永远是同一项，钩子只需看结构 |
| P13 | `<Show on="expand|collapse">` 走源头登记，同 `IToggleSource.RegisterCheckedShow`：<br>• 接口：`IExpandable.RegisterExpandShow(bool want, Action reevaluate)`；<br>• Collapsible 在 `EstablishInitialState`、`AdjudicateGroup`、`Expand`、`Collapse` 里重算；<br>• TabMenu、Popover 在开、关时重算 | Collapsible 在自己的 `OnAfterApply` 里静默定初态（`Collapsible.cs:658-663`）；手风琴的 `AdjudicateGroup` 排在 Show 之后的 `DeferDuringOpen` 里静默翻转；动态行里则什么都不推迟。只靠订阅事件，这三种情况都会错 |
| P14 | `PUI-SHOW-EXPAND-SELF` 做成自带祖先状态的整屏遍历，照 `CooldownRules.CheckSources` 的写法。状态在每个源处覆盖：<br>• Popover / TabMenu 的子孙：真；<br>• Collapsible 的 body：真；<br>• Collapsible 的 `<Header>`：假；<br>• 模板调用：复位，交给展开遍。<br>TabMenu 的 `itemTemplate` 行两遍都看不到，README 里写明 | `IRWalker` 的祖先旗标只会被「或」上去，表达不了「最近的源」 |
| P15 | hug 与布局组相关的扩展：<br>• `HugRules.HugTags` 与 `CheckHugStretchChild` 的轴表加 Popover；不写 height 视同 hug。<br>• 两处「父节点是布局组」的硬编码表加 Popover：`IRWalker.cs:360-361`、`ScreenInstantiator.cs:383-384`。<br>• 父节点一侧对 `<Popover>` 子节点的布局检查一律跳过，Popover 节点自身也跳过；这些问题只由 `PUI-POPOVER-*` 报。跳过的检查：`LayoutGroupChildRules.CheckChild` / `CheckNonLayoutChild`、`MarginAnchorRules`、Grid 子尺寸 | 浮层不在任何流里。`HasHug` 看不到默认 hug；父侧的检查只会重复报，有的还会报错 |
| P16 | `Insert` 的光标记录，从两处取：<br>• `PuiInputField.LateUpdate`：编辑期间每帧记；<br>• 覆写的 `OnDeselect`：在调 base 之前记，并把 base 将要追加的组字串长度算进去。<br>其他约定：<br>• 「在不在编辑」看 `InputField.IsEditing`，所以认 `SetEditingForTests`；<br>• 只读时拒绝；<br>• 夹到文字长度由我们自己做；<br>• EditMode 用 `RememberCaretForTests(anchor, focus)`；<br>• 「不发 `OnInput`」放 PlayMode 测 | EditMode 不跑 `LateUpdate`，TMP 也进不了编辑态，`OnInput` 在 EditMode 本来就发不出来。另外，Editor 非 Play 时 `SetText` 不夹光标 |
| P17 | 过渡改为补间一个位移分量，每帧写 `rest + offset`；`Reposition` 只更新 `rest` | 今天滑入补间直接占着 `anchoredPosition`（`PopupCore.cs:276-282`），过渡期间的任何 `Reposition` 都会被它盖掉，面板停在旧位置。候选列表在打开过渡里推送时同样中招 |
| P18 | 关闭时 `CanvasGroup.blocksRaycasts = false`，打开时恢复 | 淡出期间面板还在挡指针，按在一个正在淡出的子层上，会被当成「外面」，把父层一起关掉 |
| P19 | `PopupCore` 找根 Canvas 时，宿主就是面板的情况下从 `_panel.parent` 开始找；焦点的还原目标永远不能是正在关的面板 | 不改的话，会先找到面板自己的嵌套 Canvas，算出错误的 `HostRootOrder`，遮罩也会挂到面板下面 |
| P20 | 探测按下的方式：<br>• Input System：在 `InputSystem.onAfterUpdate` 里锁存（跳过编辑器更新），探测在 `Update` 里消费；<br>• 旧输入：用 `#elif ENABLE_LEGACY_INPUT_MANAGER`；<br>• 守卫带 `[DefaultExecutionOrder(-1000)]`，判定发生在 EventSystem 处理这次按下之前；<br>• `PuiDropdown.ExpandedCount > 0` 时不探测 | Fixed / Manual 更新模式下，`wasPressedThisFrame` 和帧对不上。只开 Input System 时，旧 `Input` 会抛错。浮层里 `<Dropdown>` 的列表挂在根 Canvas 下，在列表里选一项会被当成「外面」：浮层一关，这次选择就丢了 |
| P21 | 动态子树里的 `@id` 解析统一推迟到实例化收尾：<br>• 新增 `ScreenInstantiator.DeferAfterBuild`：深度计数 + try/finally；<br>• 冲刷点：`InstantiateNode`（`ReplaceScopedIds` 之后）、内联路径的 `ApplyAddBlock`；<br>• 适用对象：`<Trigger>` / `<Animation>` / `<Show>` 的 `@id`，以及 Popover 的 `on=`。<br>Red 先行 | 动态行是逐节点立刻应用属性的，后面兄弟节点的 id 这时还不存在。表情布局正好会撞上：触发钮里的 `<Show on="expand@pop">` 写在 Popover 前面 |
| P22 | 只有 Canvas 尺寸变了才重新选侧；软键盘带来的边界变化，只按锁定的侧重新夹边 | 软键盘的区域会连续几帧变化，按边界变化解锁会让面板来回翻面 |
| P23 | 宿主被盖住时打不开：宿主根序低于最上层模态，或 Loading 正在显示 | 否则代码在下层模态里打开的浮层，会画在上层模态之上 |
| P24 | 关闭原因的细则：<br>• `OnHostAfterApply`：不可交互 → `Code`，失活 → `HostGone`；<br>• `AnchorLost` / `HostGone`：选中项还原到打开时的那一个，没有就清空，不还原到锚点（锚点可能已经被回收去显示别的项）；<br>• `Dispose`：开着就先发 `OnClosed(HostGone)`，再释放各个 subject；<br>• 重入守卫：关闭回调里打开别的浮层、`Replaced` 的回调里调 `Close()`，都不能留下僵尸项 | 让 §4.4 的表与实际路径一一对应 |
| P25 | 圈闭时，把面板里的活 Selectable（包括 BindItems 建出的行）也转换成圈在面板内的显式导航 | `ExplicitNavigationResolver` 只转换 `_nodeMap` 里的节点（`:48-58`）。表情格会从面板边缘走出去，再被圈闭拉回第一格 |
| P26 | 新增两条 lint：<br>• `PUI-POPOVER-PARENT`：Popover 是 `<ScrollList>` / `<TabBar>` / `<TabMenu>` / `<Carousel>` / `<Pages>` 的直接子元素（会被当成行、页签、页），或写在 `<Btn>` / `<Tab>` / `<Toggle>` 里面（面板会继承悬停、按下、置灰的视觉）；<br>• `PUI-POPOVER-HUG-WIDTH`：宽度 hug，而所有子元素都是 `width="stretch"`，面板宽为 0 | 两种都是写了能跑、但结果一定错的结构 |

## Global Constraints

- **分支与语言**：
  - 在 `feat/popover` 上做，**绝不提交到 main**。
  - LangVersion 9.0：不用 primary constructor、`[]`、`[field: SerializeField]`、`record`。
  - 不用 `System.Threading` / `Task`（WebGL），异步用 `Awaitable`。
- **Core 纯 C#**：
  - `Runtime/Core/Lint/*` 不 `using UnityEngine`，也不依赖 `PromptUGUI.Application`。
  - `SizeSpec` 不在 CLI 的编译集里，`PUI-POPOVER-SIZE` 照 `HugRules.IsHugValue` 的写法匹配字符串。
- **属性与事件**：`[UIAttr]` 必须同时带 `[Preserve]`；事件一律是 `Observable<T>`。
- **R3 吞异常**：`OnNext` 里抛的异常只记日志，不会抛回推送方。测试用 `LogAssert.Expect(LogType.Exception, regex)`，不用 `Assert.Throws`。
- **Red 先行**。每个 Task 收尾跑 lint：`cd .lint && dotnet format --verify-no-changes --severity warn PromptUGUI.Lint.slnx`。**禁止** `--severity info`。
- **UIXmlLint**：动过 `Core/Lint` 或任何 `.ui.xml` 后，跑 `dotnet run --project .lint/UIXmlLint -- Runtime/Resources/`；改了样例再加 `Samples~/CommonControls/Resources/`。
- **测试只经 Unity MCP**；**禁止** `execute_menu_item("Assets/Reimport All")`。
- **EditMode 的限制与对策**：
  - 限制：
    - `Update` / `LateUpdate` / LitMotion 都不跑；
    - `Time.frameCount` 在 `[Test]` 内不前进；
    - `EventSystem.current` 恒为 null；
    - Overlay Canvas 没有确定的尺寸；
    - 没有 `[ExecuteAlways]` 的 MonoBehaviour 收不到 `OnEnable` / `OnDisable`；
    - EditMode 测试程序集不引用 Input System / LitMotion。
  - 对策：
    - host 写 `anchor='center'`，配合 `PopupBounds.BoundsOverride`；
    - 需要布局结果时调 `Canvas.ForceUpdateCanvases()`；
    - EventSystem 自建自毁，照 `PuiInputFieldTests` 的写法；
    - 依赖上述能力的断言放 PlayMode，或者用测试钩子。

  - 待清理旗标。
