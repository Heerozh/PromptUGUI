# Layered painting workflow — refined `.pxl` art

Use this for fully-shaded, illustrative sprites (~24×24 and up — unit portraits, C&C-style build-button icons, decorated props). Simple UI chrome (9-slice frames, flat glyphs) stays flat single-`grid:`; this workflow's whole point is that shading, anti-aliasing, and highlights each live on their own layer, so refining one never disturbs another.

Everything here was validated by actually painting a 32×32 tank icon this way (full file at the bottom).

## The five layers

Declare **named `layer:` blocks only** (no anonymous `grid:`) so the stack is self-documenting, bottom → top:

| # | layer | new colors | job |
|---|---|---|---|
| 1 | `silhouette` | 1 | The whole shape as a filled blob in the image's **darkest** color |
| 2 | `base` | ≤5 | Big color blocks + basic shadow. **Structure freezes here** |
| 3 | `aa` | ≤5 (usually 2) | Anti-alias jagged **internal** color boundaries |
| 4 | `shade` | 0–5 | Enrich light/dark regions: gradients, cast shadows. Brightness only |
| 5 | `highlight` | 1–3 | Material-appropriate highlights; selective outlining |

**1. `silhouette`** — paint the entire shape solid with the darkest color. Because it is the darkest color it doubles as both the outline and the default deepest-shadow: every later layer paints 1px *inside* the silhouette, so the leftover rim IS the 1px outline, and any pixel you forget to paint reads as intentional shadow instead of a hole. Get proportions right here — this is the cheapest layer to redraw.

**2. `base`** — block in local colors and the basic shadow split. Two hard rules:

- **Declare the light source in a file-header comment now** (e.g. `# Light source: TOP-LEFT (fixed for all layers)`) and obey it in every later layer.
- **Structure is frozen after this layer.** Layers 3–5 only adjust light and dark; they never move an edge or reshape an element. So iterate on `base` until *every structural element reads in the render* — if a part is illegible (too small, too dark, wrong shape), fix it here, not later. This is also why `aa` can safely run as step 3: nothing after it changes the boundaries it smoothed.

**3. `aa`** — smooth staircase edges between color regions with opaque mid-tones. Before minting a new color, check whether an existing ramp color already sits between the two neighbors; the transition color is by definition their midpoint, so reuse is common. **Internal boundaries only — never anti-alias the outer edge against transparency**: the runtime background is unknown, and AA pixels there become dirty fringe on any background that isn't the one you imagined.

**4. `shade`** — enrich: directional gradients across large faces (toward the declared light), cast shadows (turret onto hull deck), deepened crevices, darkened undersides. Reuse base/aa colors where they fit (a cast shadow is usually just the existing shadow color). If you catch yourself moving an edge, stop — that is a `base` fix.

**5. `highlight`** — the pop layer. Match the material: matte steel gets thin edge-lights, not glossy blobs. The key move is **selective outlining (selout)**: replace outline pixels on the light-source side with the highlight color — a lit top edge is what lifts an icon off a dark button face. Spend the brightest color in single-pixel doses (the tank uses its brightest color exactly once).

## Color budget

- **≤5 *new* colors per layer, reuse-first** — always ask "does an existing color already work?" before adding one.
- **Total ~12–16 colors at 32×32**; fewer at smaller sizes. The per-layer cap alone would allow 20+, which turns to mud — the total cap is the real limit.

## The loop — after EVERY layer

1. Render: `dotnet run --project .lint/PxlPreview -- <file>.pxl --scale 16 --layers`
2. **Read the PNG** — each layer pane *and* the composite. Some mistakes are invisible in the text and only appear in the render: in the tank, road wheels first drawn as 1px crosses read as nothing against the dark track (caught in the `base` render, cheap to fix; caught later it would have meant reworking upper layers), and whether a cast shadow lands in the right place is only judgeable in the composite.
3. Structure-invariant check: run `--emit-flat` and compare each row's first/last non-`.` column against the `silhouette` layer — spans must match exactly. Selout pixels in `highlight` may *recolor* a boundary pixel but never move it.

Pitfalls hit in practice:

- **Row count** is the layered equivalent of the flat format's row-width error: appending a 33-row block to a 32-row section fails with `layer 'base' has 33 rows but layer 'silhouette' has 32`. Count rows when appending.
- **Compositing is pure overwrite, top layer wins.** Stacked contributions can collapse: a wheel's bottom row got the wheel color from `base`, corner AA from `aa`, and a center-darkening pixel from `shade` — the flat shows the whole row in the AA color. Judge the flat/composite, not your intent per layer.

## Worked example — 32×32 tank build-button icon

12 colors across 5 layers. `K`/`S`/`A` are reused by later layers (cast shadow, wheel shading); `X` appears on exactly one pixel.

| char | hex | introduced by | role |
|---|---|---|---|
| `K` | `#14160f` | silhouette | darkest: outline + deepest shadow |
| `L` | `#7d8c4b` | base | lit top surfaces |
| `B` | `#5c6a33` | base | base olive (vertical faces) |
| `S` | `#3a4522` | base | shadow olive (reused in `shade` as cast shadow) |
| `W` | `#5a5f4a` | base | road wheels |
| `T` | `#2b2e21` | base | track band (separates tracks from pure black) |
| `A` | `#3a3e30` | aa | wheel↔track mid (reused in `shade` for wheel bottoms) |
| `G` | `#6b7a3f` | aa | L↔B mid |
| `D` | `#20250f` | shade | deep shadow (undersides, rear corner) |
| `M` | `#90a05a` | shade | upper-mid light (light-facing gradient ends) |
